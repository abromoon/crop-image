# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Что это

Название проекта — **SNIP** (Simple No-upload Image Processing); так он
подписан в шапке, `<title>` и манифесте. Внутренние идентификаторы
(`crop-image:theme` в `localStorage`, `CACHE_NAME` в `sw.js`, имя репозитория)
намеренно остались `crop-image` — их смена сбросит тему и кэш у пользователей.

Два независимых способа обрезать изображение (веб-версия — по выбранным
пропорциям: квадрат, форматы обоев рабочего стола или свои; CLI — в квадрат) с
выбором якоря (сверху / по центру / снизу / слева / справа): статическая веб-страница для GitHub Pages
(папка `src/`: `index.html` + `style.css` + `app.js`) и отдельный CLI-скрипт на Python
(`crop_image.py`). Веб-версия, кроме обрезки по пропорциям, умеет второй сервис —
обложки для библиотеки Steam (основное, фон, логотип, широкое) и аватары
(квадрат 1:1 любого размера с превью в разных размерах и скруглениях); в CLI их нет.
Между ними нет общего кода и зависимостей — это две разные
реализации одной идеи, живущие в одном репозитории.

Ключевое инвариант веб-версии: изображение никогда не покидает браузер — нет
бэкенда, нет загрузки на сервер, нет cookies, нет истории между сеансами.
Единственное, что пишется в `localStorage`, — ключ `crop-image:theme` с
выбором темы; данные изображения, имя файла и параметры обрезки не
сохраняются. В Cache Storage service worker держит только файлы приложения
(`APP_SHELL`); файл, присланный через «Поделиться», живёт в памяти SW до
передачи странице и никуда не пишется. Сохраняй это свойство при любых
изменениях `app.js` и `sw.js`.

## Команды

Сборки, линтеров и тестов в проекте нет.

- Запуск веб-версии локально: открыть `src/index.html` в браузере, либо поднять
  любой статический сервер из `src/` (например, `python3 -m http.server -d src`
  из корня репозитория). Service worker (офлайн, «Поделиться») работает только на
  `localhost`/HTTPS, не на `file://`; после правок файлов приложения первая
  перезагрузка отдаёт старую версию из кэша (stale-while-revalidate) — для
  отладки включи в DevTools «Update on reload» или перезагрузи дважды.
- Запуск CLI-версии: `python3 crop_image.py путь/к/image.png [output_dir_or_prefix]`
  (зависимость — Pillow: `pip install Pillow`).

## Архитектура веб-версии

Вся логика — в одном файле `app.js`, без сборки и фреймворков:

- Состояние приложения — единственный объект `state` (файл, object URL,
  загруженный `HTMLImageElement`, размеры). UI переключается между двумя
  секциями: `#start` (заголовок + `#dropzone`, выбор файла) и `#editor`.
- Сервисы (`SERVICES`: «Обрезка по пропорциям», «Обложки Steam» и «Аватары») —
  это один документ, выбор по hash: `#ratio` (и пустой/неизвестный hash, в том
  числе старый `#square`), `#steam` или `#avatar`. Отдельный `.html` не годится: `sw.js` отдаёт
  `index.html` на любую навигацию. `applyService()` (на старте и по
  `hashchange`) меняет `document.title`, заголовок стартового экрана,
  `summary` меню и `aria-current` у ссылок; смена hash не перезагружает
  страницу, поэтому открытая картинка переживает переключение. Новый сервис =
  запись в `SERVICES` + ссылка `href="#name" data-service="name"` в меню.
- Пресет рамки возвращает `currentPreset()`, у обоих сервисов одной формы:
  `ratio` — пропорции рамки максимального размера (`null` у логотипа —
  свободная рамка), `suffix` для имени файла, `exportTypes` — какие форматы
  сохраняются как есть, `target` — рекомендуемый размер Steam (только справка
  в инфо, результат **никогда не масштабируется**), `userRatio` — пропорции
  выбраны пользователем, `resize` — рамку можно тянуть за ручки: `"free"`
  (логотип, 8 ручек) или `"square"` (аватар, только углы), `noAnchorSuffix` —
  без якоря в имени файла. В сервисе «по пропорциям» пресет собирается на лету
  из `ratioPref`, в Steam — `STEAM_PRESETS[presetPref]` (`presetPref`, как и
  `anchorPref`, вне `state` и только в памяти). Всё пересчитывает
  `applyPreset()`; видимость инструментов (`#ratio-tool`, `#preset-tool`,
  `#avatar-tool`, `#anchor-tool`, `#logo-tool`) и превью аватара
  (`#avatar-preview`) — `updateToolsUI()`.
- Аватары (`service === "avatar"`): пресет `{ ratio: [1, 1], resize: "square" }`,
  рамка — квадрат любой стороны, а не только максимальной. Сторона хранится в
  `avatarSide` (вне `state`, только в памяти; `null` — максимум; сбрасывается
  при новой картинке и смене сервиса), меняется полем `#avatar-size` (рамка
  растёт/сжимается вокруг центра) или угловой ручкой (`squareResizedCrop`:
  противоположный угол неподвижен, прилипание к максимуму); перемещение
  сторону не меняет. Т. к. свободны могут быть обе оси, якорь здесь — это
  клетка, на позиции которой рамка стоит точно (`syncAnchorWithCrop`,
  `updateAnchorUI`), без «эквивалентных» клеток; иначе «Вручную». Имя файла —
  `<имя>_avatar_<сторона>.<ext>`. Превью (`updateAvatarUI`) — CSS-плитки
  `.avatar-tile` с фоном из `state.objectUrl` (переменные `--av-img/w/h/x/y` на
  `#avatar-preview`), без перекодирования; плитки задают `--size` и `--round`
  в `index.html`.
- Раскладка `#editor` — CSS Grid из трёх зон: `.editor__tools` (слева,
  инструменты обрезки; новый инструмент = новая `.tool` в этой колонке),
  `.editor__stage` (центр: превью и под ним кнопки «Другое»/«Скачать»,
  полные подписи — в `title`), `.editor__info` (справа: `.info-panel` и
  `#format-note`). ≤ 1100px инфо уходит под инструменты, ≤ 720px — одна
  колонка в порядке превью → инструменты → инфо. Превью вписывается в ширину
  центра и в высоту экрана (`max-height` у `#preview-img`). Ширина страницы
  задаётся `--page-max`/`--gutter` в `:root` — общими для `main` и шапки.
- Пропорции — первый `.tool` в левой колонке: список `#ratio-select` (пресеты —
  `<option value="16:9" data-hint="…">`: 1:1, 16:9, 16:10, 21:9, 32:9, 3:2, 4:3,
  5:4; значение и есть пропорции, отдельной таблицы в JS нет — плюс «Свои…»
  с полями `#ratio-w`/`#ratio-h`, целые 1…9999, валидность — нативная). Выбор хранится в `ratioPref`
  `[rw, rh]` — вне `state`, как и `anchorPref`, только в памяти. Рамка в этом
  сервисе всегда максимального размера для картинки (`fitRatio`), без ресайза; из-за целых
  пикселей пропорции могут отличаться на полпикселя — тогда в инфо-панели
  «≈ 21:9». Пропорции не сокращаются (21:9 не становится 7:3): они же идут в
  имя файла (`_21x9_`, для 1:1 — `_square_`). Новые пропорции сбрасывают
  `state.manual` и ставят рамку по выбранному якорю (`applyRatio`).
- `state.crop` (`{ x, y, w, h }` в пикселях исходника) — единственный источник
  истины для области обрезки: из него рисуется оверлей (`updateOverlay`) и
  делается реальная обрезка при экспорте. Заполняется двумя путями:
  `applyPreset()` при выборе якоря/пропорций/сервиса (через
  `computeCropBox(anchor, w, h, ratio)`) и ручным перетаскиванием рамки
  (Pointer Events на `#preview-frame`).
- Якорь выбирается сеткой 3×3 кнопок `[data-anchor]` (таблица `ANCHORS`,
  `col`/`row` 0…2, включая диагонали). Выбор хранится в `anchorPref` — вне
  `state`, чтобы пережить «Другое», и только в памяти. Т. к. рамка максимального
  размера упирается в картинку по одной оси, свободна (`freeSpace()`) не больше
  чем одна: `effectiveAnchor(anchor, free)` сводит якорь к
  `left|center|right` (место по горизонтали) или `top|center|bottom` (по
  вертикали) — по нему подсвечиваются эквивалентные клетки (`.is-equivalent`)
  и строится суффикс имени файла; если свободного места нет (картинка уже
  нужных пропорций), сетка disabled. Всё состояние сетки рисует `updateAnchorUI()`
  (вызывается из `updateOverlay`).
- При перетаскивании рамка прилипает к позициям якорей в пределах `SNAP_PX`
  экранных пикселей; `syncAnchorWithCrop()` затем либо меняет в `anchorPref`
  только подвижную ось (ряд/колонка второй оси сохраняются), либо ставит
  `state.manual` — режим «Вручную»: ни одна кнопка не нажата, в сетке видна
  точка `#anchor-marker` с фактическим положением рамки, суффикс файла `custom`.
- Логотип Steam (`ratio: null`): стартовая рамка — `opaqueBounds()`, границы
  пикселей с `alpha > 0` (читаются через `getImageData` один раз, кэш в
  `state.opaque`; у JPEG не читаются). Рамку можно тянуть за 8 ручек
  `.crop-handle[data-handle]` внутри `#crop-overlay` (видны с классом
  `crop-overlay--resizable`): `resizedCrop()` двигает края независимо, кламп к
  картинке и `MIN_FRAME_PX`, прилипание к краям картинки и границам
  непрозрачного. У фиксированных пропорций ручек нет — рамка всегда
  максимальная. Кнопки `#trim-btn`/`#full-btn` возвращают рамку к
  `opaqueBounds()`/всему изображению.
- Обрезка выполняется через Canvas API (`drawImage` с исходными и целевыми
  прямоугольниками) — это единственный способ получить пиксельно точный кроп
  в браузере. Кодирование вынесено в `renderCropBlob()`: им пользуются и
  скачивание, и оценка веса результата.
- Панель информации (`.info-panel` в правой зоне): ячейки размечены
  `data-info="…"` и заполняются через `setInfo`. `updateSourceInfo()` —
  один раз при загрузке; `updateOutputInfo()` вызывается из `updateOverlay`
  и обновляется вживую при перетаскивании. Строка «Steam» (`#target-info`,
  обёртка `.info-list__row` с `display: contents`) видна только у пресетов
  с `target`. Вес результата известен только
  после кодирования, поэтому `scheduleSizeEstimate()` кодирует кроп с
  debounce после смены якоря/конца перетаскивания и отбрасывает устаревшие
  ответы по счётчику `sizeSeq`.
- Экспорт формата: `pickExportType` сохраняет формат как есть, если он в
  `exportTypes` текущего пресета, иначе — PNG. «По пропорциям» —
  `CANVAS_EXPORTABLE_TYPES` (PNG без потерь; JPEG/WebP перекодируются с
  `quality = 1.0`, так как Canvas не умеет резать JPEG на уровне DCT-блоков),
  Steam — `STEAM_EXPORTABLE_TYPES` (PNG/JPEG: WebP в Steam не гарантирован),
  логотип — только PNG (альфа). `updateFormatNote` отражает это в UI — при
  добавлении форматов или пресетов обнови обе функции согласованно.
- Скачивание файла — через временный `<a download>` + `URL.createObjectURL`,
  без сетевых запросов.
- Шрифты: `--font-text` (Roboto Flex — основной текст) и `--font-display`
  (Google Sans — заголовки, подписи инструментов, шапка, кнопки) в `:root`.
  Файлы — свои, в `src/fonts/` (woff2, подмножества latin + cyrillic, оси
  `wght` 400–700, у Roboto Flex ещё `opsz`; рядом OFL-лицензии). Google Fonts
  CDN не подключать: это запрос к третьей стороне на каждом заходе и потеря
  шрифта офлайн. Google Sans Flex не годится — в нём нет кириллицы. Новый
  файл шрифта → `@font-face` с `unicode-range` + `APP_SHELL` + бамп `CACHE_NAME`.
- Иконки: Material Symbols Rounded (вес 400, без заливки) как inline SVG —
  `<svg class="icon" viewBox="0 -960 960 960" width="20" height="20"
  aria-hidden="true"><path d="…"/></svg>`, `path` берётся из
  `fonts.gstatic.com/s/i/short-term/release/materialsymbolsrounded/<name>/default/24px.svg`.
  Цвет — `fill: currentColor` из `.icon`. Логотип и PWA-иконки (`icons/`) — свои.
- Тема: цвета — CSS-переменные в `:root` (`style.css`). Тёмный набор
  описан дважды — под `prefers-color-scheme: dark` (режим «Авто») и под
  `:root[data-theme="dark"]`; меняя цвета, правь оба блока. Переключатель
  «Авто / Светлая / Тёмная» (иконки) в шапке сайта выставляет `data-theme` на
  `<html>` (`applyTheme`/`saveTheme` в `app.js`), а inline-скрипт в `<head>`
  `index.html` применяет сохранённую тему до загрузки стилей, чтобы не было
  мигания.
- Шапка сайта `.site-header` (над `<main class="app">`, во всю ширину, не
  закреплена; футер `.site-footer` — после `main`): логотип → меню сервисов → переключатель темы. Меню — нативный
  `<details class="service-menu">`; `app.js` только закрывает его по клику
  снаружи и по Escape. Пункты меню — ссылки на hash (см. «Сервисы»
  выше); `aria-current`, галочку и `summary` выставляет `applyService()`.

## PWA

- `manifest.webmanifest` — установка как приложение, `shortcuts` на
  `./#ratio`, `./#steam` и `./#avatar`, плюс `file_handlers`
  (открытие картинок из ОС, Chromium на десктопе) и `share_target` (приём фото
  через «Поделиться», в основном Android). Иконки — в `icons/`, PNG отрендерены
  из `icons/icon.svg` (maskable и apple-touch — тот же SVG без скругления).
- `sw.js` — precache `APP_SHELL` при установке, затем stale-while-revalidate:
  отдаёт из кэша и обновляет в фоне (`cache: "no-cache"`, чтобы обойти
  HTTP-кэш Pages), так что новая версия видна со следующего запуска. Кэшируется
  только то, что уже есть в `APP_SHELL`; навигации отдают `index.html`.
  Добавляешь файл приложения — внеси его в `APP_SHELL` и бампни `CACHE_NAME`
  (бамп нужен только при смене состава кэша, не при каждой правке).
- «Поделиться»: SW перехватывает POST на `share-target`, держит файл в
  переменной и делает 303 на `./?share-target`; `app.js` забирает файл
  сообщением `get-shared-file` через `MessageChannel`. Открытие из ОС —
  `launchQueue.setConsumer` в `app.js`. Оба пути сходятся в `loadFile()`.
- Сайт живёт в подпапке (`/<repo>/`), поэтому все пути в манифесте, SW и
  `<head>` относительные.
- `meta[name=theme-color]` (цвет заголовка окна) синхронизируется с ручным
  выбором темы в `applyTheme`.

## Архитектура CLI-версии

`crop_image.py` — самостоятельный скрипт без общего кода с веб-версией.
Отличие в поведении: он всегда создаёт **две** копии за один запуск — с
якорем сверху и снизу (`crop_square_both`), а не одну по выбранному якорю.
Использует `Image.crop()` из Pillow, который для lossless-форматов работает
на уровне пикселей без перекодирования содержимого.

## Деплой

`.github/workflows/deploy.yml` публикует содержимое папки `src/` как есть
(без шага сборки) на GitHub Pages при каждом push в `main`; всё вне `src/`
(CLI, документация) на сайт не попадает. Все пути внутри `src/` относительные —
папку можно публиковать как корень сайта или из подкаталога. Требует
одноразовой настройки в репозитории: Settings → Pages → Build and
deployment → Source: GitHub Actions.
