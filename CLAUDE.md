# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Что это

Название проекта — **SNIP** (Simple No-upload Image Processing); так он
подписан в шапке, `<title>` и манифесте. Внутренние идентификаторы
(`crop-image:theme` в `localStorage`, `CACHE_NAME` в `sw.js`, имя репозитория)
намеренно остались `crop-image` — их смена сбросит тему и кэш у пользователей.

Два независимых способа обрезать изображение в квадрат с выбором якоря (сверху /
по центру / снизу / слева / справа): статическая веб-страница для GitHub Pages
(папка `src/`: `index.html` + `style.css` + `app.js`) и отдельный CLI-скрипт на Python
(`crop_image.py`). Между ними нет общего кода и зависимостей — это две разные
реализации одной идеи, живущие в одном репозитории.

Ключевое инвариант веб-версии: изображение никогда не покидает браузер — нет
бэкенда, нет загрузки на сервер, нет cookies, нет истории между сеансами.
Единственное, что пишется в `localStorage`, — ключ `crop-image:theme` с
выбором темы; данные изображения, имя файла и параметры обрезки не
сохраняются. В Cache Storage service worker держит только файлы приложения
(`APP_SHELL`); файл, присланный через «Поделиться», живёт в памяти SW до
передачи странице и никуда не пишется. Сохраняй это свойство при любых
изменениях `app.js` и `sw.js`.

## Команды

Сборки, линтеров и тестов в проекте нет.

- Запуск веб-версии локально: открыть `src/index.html` в браузере, либо поднять
  любой статический сервер из `src/` (например, `python3 -m http.server -d src`
  из корня репозитория). Service worker (офлайн, «Поделиться») работает только на
  `localhost`/HTTPS, не на `file://`; после правок файлов приложения первая
  перезагрузка отдаёт старую версию из кэша (stale-while-revalidate) — для
  отладки включи в DevTools «Update on reload» или перезагрузи дважды.
- Запуск CLI-версии: `python3 crop_image.py путь/к/image.png [output_dir_or_prefix]`
  (зависимость — Pillow: `pip install Pillow`).

## Архитектура веб-версии

Вся логика — в одном файле `app.js`, без сборки и фреймворков:

- Состояние приложения — единственный объект `state` (файл, object URL,
  загруженный `HTMLImageElement`, размеры). UI переключается между двумя
  секциями: `#dropzone` (выбор файла) и `#editor` (превью + обрезка).
- `state.crop` (`{ x, y, side }` в пикселях исходника) — единственный источник
  истины для области обрезки: из него рисуется оверлей (`updateOverlay`) и
  делается реальная обрезка при экспорте. Заполняется двумя путями:
  `applyAnchor()` при выборе якоря (через `computeCropBox(anchor, w, h)`) и
  ручным перетаскиванием рамки (Pointer Events на `#preview-frame`). При
  ручном сдвиге селектор переключается на скрытую опцию `custom` («Вручную»).
- Обрезка выполняется через Canvas API (`drawImage` с исходными и целевыми
  прямоугольниками) — это единственный способ получить пиксельно точный кроп
  в браузере. Кодирование вынесено в `renderCropBlob()`: им пользуются и
  скачивание, и оценка веса результата.
- Панель информации (`.info-panel` рядом с превью): ячейки размечены
  `data-info="…"` и заполняются через `setInfo`. `updateSourceInfo()` —
  один раз при загрузке; `updateOutputInfo()` вызывается из `updateOverlay`
  и обновляется вживую при перетаскивании. Вес результата известен только
  после кодирования, поэтому `scheduleSizeEstimate()` кодирует кроп с
  debounce после смены якоря/конца перетаскивания и отбрасывает устаревшие
  ответы по счётчику `sizeSeq`.
- Экспорт формата: `LOSSLESS_TYPES`/`CANVAS_EXPORTABLE_TYPES` определяют, что
  Canvas может сохранить напрямую (PNG всегда без потерь; JPEG/WebP
  перекодируются с `quality = 1.0`, так как Canvas не умеет резать JPEG на
  уровне DCT-блоков). Всё остальное принудительно экспортируется как PNG.
  `updateFormatNote` отражает это предупреждение в UI — при добавлении новых
  форматов обнови обе функции (`pickExportType`, `updateFormatNote`)
  согласованно.
- Скачивание файла — через временный `<a download>` + `URL.createObjectURL`,
  без сетевых запросов.
- Тема: цвета — CSS-переменные в `:root` (`style.css`). Тёмный набор
  описан дважды — под `prefers-color-scheme: dark` (режим «Авто») и под
  `:root[data-theme="dark"]`; меняя цвета, правь оба блока. Переключатель
  «Авто / Светлая / Тёмная» (иконки) в шапке сайта выставляет `data-theme` на
  `<html>` (`applyTheme`/`saveTheme` в `app.js`), а inline-скрипт в `<head>`
  `index.html` применяет сохранённую тему до загрузки стилей, чтобы не было
  мигания.
- Шапка сайта `.site-header` (над `<main class="app">`, во всю ширину, не
  закреплена): логотип → меню сервисов → переключатель темы. Меню — нативный
  `<details class="service-menu">`; `app.js` только закрывает его по клику
  снаружи и по Escape. Новый сервис = новая ссылка в `.service-menu__list`
  (у текущего — `aria-current="page"`) и его название в `summary`.

## PWA

- `manifest.webmanifest` — установка как приложение, плюс `file_handlers`
  (открытие картинок из ОС, Chromium на десктопе) и `share_target` (приём фото
  через «Поделиться», в основном Android). Иконки — в `icons/`, PNG отрендерены
  из `icons/icon.svg` (maskable и apple-touch — тот же SVG без скругления).
- `sw.js` — precache `APP_SHELL` при установке, затем stale-while-revalidate:
  отдаёт из кэша и обновляет в фоне (`cache: "no-cache"`, чтобы обойти
  HTTP-кэш Pages), так что новая версия видна со следующего запуска. Кэшируется
  только то, что уже есть в `APP_SHELL`; навигации отдают `index.html`.
  Добавляешь файл приложения — внеси его в `APP_SHELL` и бампни `CACHE_NAME`
  (бамп нужен только при смене состава кэша, не при каждой правке).
- «Поделиться»: SW перехватывает POST на `share-target`, держит файл в
  переменной и делает 303 на `./?share-target`; `app.js` забирает файл
  сообщением `get-shared-file` через `MessageChannel`. Открытие из ОС —
  `launchQueue.setConsumer` в `app.js`. Оба пути сходятся в `loadFile()`.
- Сайт живёт в подпапке (`/<repo>/`), поэтому все пути в манифесте, SW и
  `<head>` относительные.
- `meta[name=theme-color]` (цвет заголовка окна) синхронизируется с ручным
  выбором темы в `applyTheme`.

## Архитектура CLI-версии

`crop_image.py` — самостоятельный скрипт без общего кода с веб-версией.
Отличие в поведении: он всегда создаёт **две** копии за один запуск — с
якорем сверху и снизу (`crop_square_both`), а не одну по выбранному якорю.
Использует `Image.crop()` из Pillow, который для lossless-форматов работает
на уровне пикселей без перекодирования содержимого.

## Деплой

`.github/workflows/deploy.yml` публикует содержимое папки `src/` как есть
(без шага сборки) на GitHub Pages при каждом push в `main`; всё вне `src/`
(CLI, документация) на сайт не попадает. Все пути внутри `src/` относительные —
папку можно публиковать как корень сайта или из подкаталога. Требует
одноразовой настройки в репозитории: Settings → Pages → Build and
deployment → Source: GitHub Actions.
